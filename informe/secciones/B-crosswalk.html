Crosswalk O*NET to ISCO-08

This appendix documents the bridge from O*NET 30.2 task statements to ISCO-08 unit groups implemented in datos/construir_crosswalk.py. Every count below is printed by the script’s log and is reproducible from the input files listed in datos/MANIFIESTO.jsonl.

Inputs

  • O*NET 30.2 Task Statements ( statements for O*NET-SOC 2019 occupations), Task Ratings (scales IM, importance, and FT, frequency) and Occupation Data (titles) (National Center for O*NET Development 2026).

  • O*NET-SOC 2010 to O*NET-SOC 2019 crosswalk, O*NET Resource Center (CSV; codes of 2010 to codes of 2019).

  • SOC 2010 to ISCO-08 crosswalk of Hardy et al. (2018), Institute for Structural Research (IBS), file soc10_isco08.dta: rows linking six-digit SOC 2010 codes to all ISCO-08 unit groups.

Steps

  1. Task weights within O*NET occupation. For each task, importance is the mean of the IM scale (1–5) and frequency is the mean category of the FT distribution (1–7, from yearly or less to hourly or more), computed as ∑kpkk/100\sum_k p_k k / 100 over the seven category percentages. Missing values are imputed with the median of each scale. The task weight is importance ×\times frequency, normalised to sum to one within the O*NET-SOC 2019 occupation, following Acemoglu and Autor (2011).

  2. O*NET-SOC 2019 to O*NET-SOC 2010. The official crosswalk is used in reverse. The six-digit SOC 2010 code is the 2010 O*NET-SOC code with its two-digit suffix removed. An O*NET-SOC 2019 code that descends from several 2010 codes ( cases) divides its mapping weight equally among them.

  3. Rescue of SOC 2010 codes absent from the IBS file. Two codes used by O*NET-SOC 2010 are not in the IBS crosswalk: 19-1020 (biological scientists, broad group used as a detailed code) and 29-2055 (surgical technologists). The rule tries, in order, the “all other” residual of the same broad group (code ending in 9), then the other detailed codes of the same broad group in ascending order, then the codes of the same minor group. It assigns 19-1020 to 19-1029, which the IBS file maps to ISCO 2131 (biologists, botanists, zoologists and related professionals), and 29-2055 to 29-2051, mapped to ISCO 3259 (health associate professionals not elsewhere classified). Both are documented here because the second is a group-level approximation rather than a conceptual match.

  4. New occupations without a 2010 ancestor. Four O*NET-SOC 2019 codes were created after the 2010 taxonomy and have no row in the crosswalk: 15-1299.04 (penetration testers), 15-1299.05 (information security engineers), 15-1299.06 (digital forensics analysts) and 15-1299.07 (blockchain engineers). They are assigned by hand to SOC 2010 15-1199 (computer occupations, all other), which the IBS file maps to ISCO 2519 (software and applications developers and analysts not elsewhere classified) and 2529 (database and network professionals not elsewhere classified), with weight one half each.

  5. SOC 2010 to ISCO-08. Each SOC 2010 code maps to kk ISCO-08 unit groups with weight 1/k1/k. In the IBS file codes map to one group, to two, to three and to four or more (maximum ). The mapping weight is multiplied by the within-occupation task weight to give the weight of each (ISCO group, task) pair, then renormalised within the ISCO group.

  6. Aggregation to pairs. The same task reached through several O*NET occupations is summed into one pair per ISCO group. The result is pairs covering distinct tasks and unit groups, with a median of tasks per group (minimum , maximum ), and distinct task sets, since some groups share exactly the same O*NET sources.

Exclusions and imputations

Military. The three armed-forces groups, 0110 (commissioned armed forces officers), 0210 (non-commissioned armed forces officers) and 0310 (armed forces occupations, other ranks), have no O*NET tasks and are excluded from the index and from the country weights.

Seven imputed groups. Seven unit groups receive no task through the chain because their SOC counterparts are residual “all other” codes that the IBS file routes elsewhere. Each inherits the task set of its three-digit minor group (all non-imputed unit groups with the same first three digits), with weights renormalised, and is flagged imputado = True so that it can be dropped in the robustness check without imputed groups:

Why not the earlier matrix

The first author’s earlier work on augmented human capital (Espinal Maya 2026a, 2026b) bridged SOC to the Colombian adaptation of ISCO-08 at one digit and distributed tasks downward, so that four-digit occupations shared task sets and the median task belonged to occupations. That matrix cannot separate a surgeon from a statistician. The chain above keeps distinct task sets across groups and is the only bridge used in this report. The occupation-level comparison indices of Chapter 3 are carried to ISCO-08 with the same chain, applied at the occupation rather than the task level.
