How to cite and use ADI

Citation

Please cite the paper for any use of the index, the atlas, the rubric or the tools.

@article{espinal2026delegation,
  title = {The Delegation Divide: An Open Index of
    AI-Agent Delegability across Occupations
    and Countries},
  author = {Espinal Maya, Cristian and
    Jim{\'e}nez Londo{\~n}o, Santiago},
  journal = {arXiv preprint},
  year = {2026},
  url = {https://github.com/Cespial/delegation-divide}
}

The repository carries the same entry in CITATION.cff and at the top of README.md; the dataset and code of this version have their own DOI on Zenodo, 10.5281/zenodo.23552918 (all versions: 10.5281/zenodo.23552917), which should be cited together with the paper when the data are used directly. The index is versioned: the paper and this report describe v2026.1. Later versions re-rate tasks against a later reference technology and are not interchangeable with this one.

Files

The release contains, under salidas/:

  • adi_isco.csv: one row per ISCO-08 unit group with ADIo\mathrm{ADI}_o, ADI3o\mathrm{ADI3}_o, ADIso\mathrm{ADIs}_o, the bootstrap interval, the four barrier shares and the number of tasks.

  • adi_pais.csv: one row per country with ADIc\mathrm{ADI}_c and its variants, the ISCO level used, the reference year, the income group and total employment.

  • adi_tarea.csv, with the task statement, the consensus level and each model’s level, and the raw model outputs (ratings_sonnet.jsonl.gz, ratings_haiku.jsonl.gz), so that any aggregation rule can be recomputed.

  • claims.jsonl: every number in the paper and this report with its identifier, value, interval and the script that produces it. The LaTeX source reads numbers from this file only.

Static JSON

Each occupation and each country is also served as a static JSON document, so that a tool or an agent can fetch one record without downloading the dataset:

BASE=https://cespial.github.io/delegation-divide
$BASE/adi/v2026.1/isco/2512.json
$BASE/adi/v2026.1/country/COL.json

The documents carry the version, the licence and the citation string in their body.

Python package

pip install adi-index

import adi
adi.lookup("2512")      # ISCO-08 code
adi.search("software")  # title substring
adi.country("COL")      # ISO 3166-1 alpha-3
adi.top(10)             # most delegable occupations
adi.cite()              # BibTeX string

The package ships the index as data and needs no network access; it exposes the same operations as the server below.

MCP server

The Model Context Protocol (MCP) is an open standard that lets an AI agent call external tools (Anthropic 2024). The server adi-mcp (PyPI; listed in the MCP registry) offers four tools:

lookup_occupation

takes an ISCO-08 code or a free-text title and returns the occupation’s levels, barriers, intervals and version.

country_profile

takes an ISO 3166-1 alpha-3 code and returns the country’s index, its variants, the ISCO level and year of the employment data, and the income group.

top_occupations

returns the nn most delegable occupations at level L2+ or L3.

cite

returns the BibTeX entry above and the dataset DOI, so that an agent that uses the index can cite it in its output.

A typical configuration for a Claude Code or similar client is:

{"mcpServers": {
  "adi": {"command": "uvx", "args": ["adi-mcp"]}
}}

Every response includes the citation string.

llms.txt

The repository root and the dataset site carry llms.txt and llms-full.txt, which summarise the paper, the headline number, the file layout and the citation in a form meant to be read by language models. Agents that index repositories should start there.
